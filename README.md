# 拾简 · 个人信息管家 Agent

一个用于记录零散想法、资料和待办的中文 Web 应用，提供关键词检索、大模型整理、基于记录的问答和阶段总结。

## 1. 项目解决什么问题

临时想法、会议资料和待办容易散落在不同地方，回查时难以找到原文，也容易遗漏下一步要做的事。拾简将这些内容放入个人资料库，帮助用户完成三个环节。

- **记录与回查** 保存标题和正文，通过关键词搜索找回内容。
- **理解与整理** 生成摘要、提取重点和待办，并关联已有记录。
- **回顾与行动** 根据资料提问，回顾阶段进展，把行动建议加入待办清单。

本地运行使用 SQLite 保存数据，适合在本机记录和开发。通过 Sites 部署后，使用云端 D1 数据库与 ChatGPT 登录，按账号隔离记录。

## 2. 主要功能

| 功能 | 实际行为 | 是否需要模型密钥 |
| --- | --- | --- |
| 快速记录 | 保存标题和正文，类别可选“想法”“资料”“待办”，支持删除 | 否 |
| 关键词检索 | 匹配标题、正文和整理结果，按创建时间倒序显示，每页 30 条 | 否 |
| 待办管理 | 显示待办记录，标记完成或重新打开 | 否 |
| 智能整理 | 生成摘要、重点、提取的待办和相关记录，并为想法或资料重新判断类别。已有待办保留类别 | 是 |
| 智能问答 | 根据选出的记录回答问题，展示引用记录与后续行动 | 是 |
| 阶段总结 | 根据最近 7、30 或 90 天创建的记录，概括主题、进展及后续行动 | 是 |

配置 `OPENAI_API_KEY` 后启用模型功能。未配置时，记录、搜索和待办功能仍可使用。

## 3. 安装方法

### 环境要求与启动

需要 Node.js 24 或更新版本，以及 npm。应用使用 Node.js 内置模块，无第三方运行依赖。使用模型功能还需要有效的 OpenAI API 密钥与网络连接。

解压源码压缩包，或克隆已经创建的 GitHub 仓库，进入包含 `package.json` 的项目根目录。以下命令假设源码目录名为 `personal-information-agent`。

```sh
cd personal-information-agent
node --version
npm --version
npm ci
npm start
```

在浏览器打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。`npm start` 会先构建页面与 Worker，再启动本地服务并自动应用数据库迁移。首次运行使用空数据库，按 `Ctrl+C` 停止服务。

本地数据保存在 `data/personal-information-agent.sqlite`，重启后继续保留。本地开发使用固定的单用户身份，绑定 `127.0.0.1`，页面显示“本地保存”。

### 配置大模型

将 `.env.example` 复制为 `.env`，填写自己的 OpenAI API 密钥，然后重新运行 `npm start`。

PowerShell 中可使用以下命令复制配置。

```powershell
Copy-Item .env.example .env
```

macOS 或 Linux 中使用以下命令。

```sh
cp .env.example .env
```

| 配置项 | 用途 | 默认值 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 服务端调用 OpenAI API 的密钥 | 空，模型功能等待配置 |
| `OPENAI_MODEL` | 模型名称，需支持代码使用的 Chat Completions、JSON 输出和 `max_completion_tokens` 参数 | `gpt-4.1-mini` |
| `PORT` | 本地服务端口 | `3000` |

密钥为空时，页面显示“模型待配置”。“模型已配置”表示服务端读到了非空配置，实际调用仍取决于密钥、模型访问权限和网络是否可用。

模型请求由服务端发送至 OpenAI，分析时会发送相关记录内容。`.env` 与本地数据库已在 `.gitignore` 中排除。云端密钥通过 Sites 的服务端环境变量配置。

## 4. 使用方法

### 记录和查找资料

1. 打开“全部记录”，在“快速记录”中选择类别。
2. 输入正文，可选填标题，然后点击“保存记录”。标题最多 120 字符，正文最多 12,000 字符。标题留空时，取正文首行的前 48 字符。
3. 配置模型后，页面会在保存后自动继续整理。模型调用失败时，已保存的原文仍可查看。
4. 在搜索框输入关键词，查找标题、正文或整理结果。搜索结果超过 30 条时，可翻页浏览。
5. 展开记录卡片，查看原文和已有整理结果。相关记录与问答引用均可点击查看原文。

### 整理内容与待办

1. 配置模型后，可在记录卡片点击“智能整理”，已有结果时按钮为“重新整理”。
2. 在“提取的待办”旁点击“加入待办”，将选中的文本保存为独立待办。
3. 打开“待办清单”，点击“标记完成”更新状态，完成后可点击“重新打开”。

### 问答与阶段总结

1. 打开“智能问答”，输入最多 800 字符的问题，点击“提问”。
2. 阅读回答、后续行动和引用记录。回答下方显示此次参考的记录条数。
3. 打开“阶段总结”，选择最近 7、30 或 90 天，点击“生成总结”。
4. 根据结果选择需要执行的行动，点击“加入待办”。

阶段范围按记录的创建时间计算。问答和阶段总结显示在当前页面，切换页面或刷新后需要重新生成。加入待办的行动会单独保存。

## 5. 输入输出实例

### 示例一 保存、搜索和完成待办

在“快速记录”中填写以下内容。

| 输入字段 | 内容 |
| --- | --- |
| 类别 | 待办 |
| 标题 | 项目上线 |
| 正文 | 检查上线资料 |

保存后，页面出现“项目上线”记录，状态为未完成。在搜索框输入“上线”可找到它。点击“标记完成”后，卡片显示“待办 · 已完成”。

也可以在本地服务启动后，用 PowerShell 调用实际接口。以下示例以空数据库、默认端口且未配置模型密钥为前提。

```powershell
$base = 'http://127.0.0.1:3000'
$headers = @{ Origin = $base }
$payload = @{
    title = '项目上线'
    body = '检查上线资料'
    kind = '待办'
} | ConvertTo-Json

$saved = Invoke-RestMethod -Method Post -Uri "$base/api/entries" `
    -Headers $headers -ContentType 'application/json; charset=utf-8' `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($payload))
$saved | ConvertTo-Json -Depth 5
```

接口返回 HTTP 201，响应结构如下。`id` 和 `created` 每次生成，示例用占位文字表示。

```json
{
  "entry": {
    "id": "<自动生成的 UUID>",
    "title": "项目上线",
    "body": "检查上线资料",
    "kind": "待办",
    "done": 0,
    "created": "<创建时间，UTC ISO 8601>",
    "analysis": null
  },
  "ai": false
}
```

继续搜索并查看结果中的关键字段。

```powershell
$query = [Uri]::EscapeDataString('上线')
$found = Invoke-RestMethod -Uri "$base/api/entries?q=$query"
$found.entries | Select-Object title, kind, done | ConvertTo-Json
```

```json
{
  "title": "项目上线",
  "kind": "待办",
  "done": 0
}
```

标记该待办完成。

```powershell
$completion = @{ id = $saved.entry.id; done = $true } | ConvertTo-Json
$completed = Invoke-RestMethod -Method Post -Uri "$base/api/complete" `
    -Headers $headers -ContentType 'application/json; charset=utf-8' `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($completion))
$completed | ConvertTo-Json
```

```json
{
  "ok": true
}
```

再次搜索时，`done` 为 `1`。直接调用保存接口只创建记录，网页中的自动整理会在保存后另行调用 `/api/organize`。

### 示例二 整理资料并提问

配置有效密钥后，在“快速记录”中输入以下内容，类别选“资料”，然后点击“保存记录”。

| 输入字段 | 内容 |
| --- | --- |
| 标题 | 产品评审记录 |
| 正文 | 今天讨论了个人资料库的搜索功能。下一步需要补充关键词搜索用例，并整理上线检查清单。 |

整理完成后，卡片展示摘要，展开卡片可查看重点、提取的待办和相关记录。以下为整理结果的**示意内容**，具体分类和措辞由模型生成。

```text
摘要
本次评审讨论了资料库搜索功能，后续需补充搜索用例并整理上线检查清单。

重点
- 讨论主题是资料库搜索功能。
- 需要完善搜索验证和上线准备。

提取的待办
- 补充关键词搜索用例。
- 整理上线检查清单。
```

提取出的每个事项旁都有“加入待办”按钮。相关记录由模型从已有候选中选择，结果可能为空。

假设资料库中只有这条记录，在“智能问答”中输入问题。

```text
搜索功能上线前还有哪些事要做？
```

以下是 `/api/ask` 返回结构的**示意输出**，用于说明页面展示的数据。模型实际生成的文本和引用可能不同。

```json
{
  "answer": "根据产品评审记录，上线前需要补充关键词搜索用例，并整理上线检查清单。",
  "actions": [
    "补充关键词搜索用例",
    "整理上线检查清单"
  ],
  "sources": [
    {
      "id": "<产品评审记录的 UUID>",
      "title": "产品评审记录"
    }
  ],
  "scope": "参考 1 条记录"
}
```

页面将 `answer` 显示为回答，将 `actions` 显示为可加入待办的后续行动，将 `sources` 显示为可点击的引用记录。

### 示例三 生成阶段总结

假设示例二的记录在最近 7 天内创建，进入“阶段总结”，选择“最近 7 天”，点击“生成总结”。以下为**示意内容**。

```text
阶段回顾
这段时间的记录聚焦于个人资料库的搜索功能评审，以及搜索验证和上线准备。

后续行动
- 补充关键词搜索用例。
- 整理上线检查清单。

引用记录
产品评审记录

参考 1 条记录
```

有可用记录时，阶段总结使用与问答相同的 `answer`、`actions`、`sources` 和 `scope` 字段。配置模型后，范围内没有记录时，返回“这段范围内还没有记录。”，行动与引用列表为空。

### 未配置模型时的输出

`OPENAI_API_KEY` 为空时，调用智能整理、问答或阶段总结接口会返回 HTTP 503。

```json
{
  "error": "模型服务待配置"
}
```

模型服务调用失败时，接口返回 HTTP 502，并提示“模型暂时无法返回结果，请稍后重试。”。前端会展示错误信息。

## 云端部署

项目保留 Sites 的 Cloudflare Worker 与 D1 部署结构。

1. 使用 Sites 创建站点，取得该站点的 `project_id`。
2. 将 `project_id` 添加到 `.openai/hosting.json`，保留 `d1` 为 `DB`。
3. 配置站点的服务端环境变量 `OPENAI_API_KEY`，按需配置 `OPENAI_MODEL`。
4. 运行 `npm run build`，通过 Sites 源码同步与发布流程保存、部署构建产物。
5. 发布流程应用 `drizzle/` 下的数据库迁移，并提供登录、身份头和 D1 绑定。

构建入口为 `dist/server/index.js`，导出 Worker 的 `fetch(request, env)`。运行时依赖 `env.DB`。API 使用 Sites 提供的 `oai-authenticated-user-id` 进行数据隔离，写请求校验同源 `Origin`。部署到其他平台时，需要先接入可信的身份认证层与相应的数据存储适配。

本地数据与云端数据分别保存。这个源码仓库包含应用和数据库结构，首次运行使用空数据库。

## 当前范围

- 资料以粘贴的文本形式记录，单条正文最多 12,000 字符。
- 自动整理在浏览器保存记录后触发。模型失败时原文保留，可在卡片上重新整理。
- 关联分析从最近最多 180 条其他记录中筛出最多 14 条候选。
- 问答从最近最多 181 条记录中按关键词匹配，最多参考 24 条。
- 阶段总结先按创建时间筛选，最多读取最近 181 条，再参考其中最多 60 条。
- 问答、总结和关联候选中的每条正文最多取前 950 字符，并附已有摘要。整理当前记录时会传入其完整正文。
- 资料库规模较大时，上述上下文限制会影响答案覆盖范围。可通过关键词检索回看完整记录。
